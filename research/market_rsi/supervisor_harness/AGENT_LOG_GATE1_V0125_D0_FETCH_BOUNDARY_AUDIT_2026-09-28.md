## Published-source findings

1. **The scientific selection is not execution authority.** `build_p0_gate1_controller_packet.py` registers opaque source/response IDs `src_` + 26 `b` characters and `rsp_` + 26 `f` characters for the official Polymarket market-scoped-trade response class (lines 108–145), but does not put a locator in the D0 object. `prospective_source_scope_decision.py` requires `scope_only_non_executable`, rejects any operational field, requires every non-authority bit to be false, and, for `first_party_document_review_only`, requires proposed provider requests and raw bytes to be zero (lines 18–54, 306–364, 367–385). Consequently the D0 cannot be passed to a network function or be interpreted as a fetch admission.

2. **There is one code-owned documentation locator and one reviewed documentation envelope.** `build_p0_gate1_controller_packet.py` maps trusted source ID `polymarket_official_trades` to exactly `https://docs.polymarket.com/api-reference/core/get-trades-for-a-user-or-markets`, scope `market-scoped trade query documentation`, and authority label `official` (lines 36–61). Its reviewed short documentation choices bind one request, 1,000,000 bytes, five minutes, and provider cost `0` (lines 62–105). The source string's SHA-256 is `2f12d47b49fc82adafda53effcc7a11edaa9fbd85a6de9b9403cc90f86cfb3fc`.

3. **The existing document capability is one-page only, but the low-level fetcher is not itself the registry compiler.** `p0_gate1_research_contract.py` registers `inspect_official_documentation` as `single_registry_document_snapshot_v1`, handler `p0_gate1_public_fetch.fetch_snapshot:v1`, with a single trusted registry document, one request and zero provider cost (lines 99–128, 184–202). A provenance-bearing legacy short choice is forced back to its trusted derived bounds (lines 269–358). The returned broker task remains plan-only with network, purchase, sealed/scored data, and formal admission all false (lines 370–410). By contrast, `p0_gate1_public_fetch._validate_url` accepts any syntactically valid HTTPS URL with no credentials, fragment, or non-443 port; it does not compare the URL, host, path, capability, or rights policy to the source registry (lines 52–60). A caller can construct a same-schema arbitrary HTTPS task and a matching admission digest. Therefore a bare task digest or the fetcher alone is not an allowlist proof. The new bridge must perform and hash-bind the exact opaque-ID → scientific source ID → complete registry-record mapping before any later admission.

4. **The existing trade-plan compiler is not reusable as the documentation bridge.** `p0_gate1_plan_compiler.py` is specific to `fetch_fixed_public_sample`, a frozen Train catalog, three sample identities and a trade endpoint request bundle. It does demonstrate the correct pattern—code-owned mapping/handler IDs, canonical manifest SHA-256, exact endpoint/requests/budget/policy, and network execution false—but it must not be relabelled as a one-page documentation request.

5. **The public fetch is one-shot and fail-closed once it receives a genuinely trusted exact task and separate admission.** `p0_gate1_public_fetch.py` requires an exact six-field admission containing the canonical broker-task SHA-256, matching source ID, literal fetch authorization, one request, and an admitted byte ceiling no greater than the task ceiling or 5,000,000-byte hard maximum (lines 93–113). `UrlLibTransport` creates one `GET`, disables redirects, sets two fixed headers, uses a 15-second timeout, and reads at most the admitted byte limit plus one byte (lines 21–49). A successful response must be exact-schema, status 200, retain the exact original URL, contain 1..limit bytes, and have an allowlisted normalized content type (lines 114–123). Output must be fresh; the body is exclusively written and re-read; the receipt records the URL, body, request count, redirect count, and non-admission boundaries (lines 124–150). The source contains no retry loop.

6. **The watched wrapper adds liveness evidence but does not add URL authority or a retry.** `p0_gate1_watched_fetch.py` hashes `{task, admission}`, claims a `research` task with stage `gate1_public_fetch`, heartbeat deadline 20 seconds and material-progress deadline 30 seconds, records a material heartbeat before the fetch, invokes the fetch exactly once, hashes the exact `receipt.json` bytes, records a second material heartbeat, and closes success with that receipt-file hash (lines 40–77). A `ValueError`/`UnicodeError` becomes `malformed_data`; other exceptions become `worker_error`; both become an incident and are re-raised. Its module contract explicitly requires a separate outer monitor for a child blocked below the transport timeout (lines 1–7).

7. **Watchdog incidents are terminal evidence, not hidden retries.** `supervisor_watchdog.py` hash-chains its journal, binds exact task/process/container identities, detects heartbeat or progress deadline breaches, freezes a complete incident packet with `automatic_retry: false` and `downstream_training_allowed: false`, prohibits same-ID retry, and permits resumption only under a fresh never-used ID after a separately verified canary (lines 116–194, 206–328, 343–410, 480–505). The watched wrapper supplies no container identity, declares data-gate evidence `unknown`, and declares budget state `none`; a later production caller/outer monitor must verify the real PID/command and absence of a container/budget allocation rather than trusting those inputs by convention.

8. **Rights and admission remain separate gates.** The tagged rights policy allows only the selected official public source with no credentials, purchase or write; forbids inferring research-use rights from technical accessibility; requires rights to remain unknown unless stated by the official source; and forbids direct formal prediction-data admission (`build_p0_gate1_controller_packet.py`, lines 18–28). `ARCHITECTURE.md` lines 139–160 requires the sequence D0 → exact request plan → separately admitted watched fetch → candidate admission → independently issued formal Train admission. `p0_gate1_public_fetch` receipts set `sealed_data_read` and `formal_data_admitted` false. `formal_train_admission.py` has an intentionally empty production commitment registry (lines 1–53). `p0_candidate_admission_integration.py` likewise identifies candidate-only output and keeps source rights, provider-origin authentication, network authority, formal Train admission, Dev/Final reads, and prediction improvement false (lines 1–8, 75–100). A documentation snapshot is evidence about a source, not an admitted prediction dataset.

## Mandatory stop conditions

- Stop offline before admission if the decision/provenance/release/source digest is missing or changed; the opaque IDs do not match the sole mapping; the complete registry record/capability differs; canonical/file hashes do not match; the output schema has missing/extra members; or any locator, method, parameter, header, limit, handler, authority, retry, credential, data role, or source record came from the model/caller rather than trusted code.
- Stop before transport unless a new, separate admission binds the exact compiled object and exact fixed limits. The existing six-field admission schema binds a broker-task hash but not a distinct new-manifest hash or rights evidence; the integration owner must either compile the exact registry-bound broker task or add an equally strict reviewed adapter. A caller-created same-schema arbitrary HTTPS task plus matching digest is insufficient.
- Stop the exact attempt on timeout, DNS/TLS/transport error, any HTTP error or non-200 status, redirect attempt, final-URL difference, malformed response fields, missing/disallowed content type, non-byte/empty/oversize body, pre-existing output, write/hash mutation, missed heartbeat/progress, process/container mismatch, or budget-state mismatch. Preserve the incident/failure without retry expansion.
- Stop after the one page. Do not follow links, call the documented API, fetch market/trade data, change parameters, or make a second request. `stop_on_first_rights_or_authority_unknown` remains true: accessibility, research-use rights, durable retention, downstream training, derived/raw redistribution, point-in-time semantics, whole-season coverage, and cryptographic provider-origin authentication remain unknown unless separately evidenced and independently reviewed. Technical accessibility, TLS success, an `official` registry label, an HTTP 200, or a content hash proves none of those rights.
- Even a valid snapshot remains documentation evidence only. It cannot enter prediction data, satisfy candidate/formal admission, open Train/Dev/Final, start training/evaluation, or establish forecast improvement.
