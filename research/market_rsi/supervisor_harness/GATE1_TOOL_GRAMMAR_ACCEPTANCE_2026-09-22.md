# Gate 1 tool grammar: predeclared acceptance boundary

Status: design before implementation. This does not admit either historical response or authorize a new provider call. It supersedes the v4 hypothesis that -02 had a well-formed extra field. The exact -02 raw response is immutable (`b34b169ba79b1ecebb55c127c350ef568a982c518f0c4454459bc1c357bcb4bb`).

The common GLM bridge may accept a complete, single tool body only when the tool name is allowed, every argument has a paired `<arg_key>…</arg_key><arg_value>…</arg_value>` sequence, every key is a nonempty ordinary identifier, keys are unique, and **all** body bytes after the name are consumed by those sequences apart from whitespace. Subsequent Gate 1 validation still requires the exact required fields and trusted source/operation/rule pairing; this grammar change does not grant permissions. The existing documented abandoned-prefix restart case may keep its behavior, but the selected completed body must pass the full grammar.

Reject before any task creation: the observed -02 mismatched tags; an unmatched `<arg_key>` tail; nested or stray argument tags; duplicate keys; malformed key names containing markup; multiple completed calls where Gate 1 allows one; and any well-formed undeclared field at the Gate 1 contract boundary. Do not silently strip text, synthesize `question_id`, reinterpret a value, or convert either old failed response into success. A synthetic well-formed call remains the positive control. Preserve exact raw text and hashes in any future failure.

Why this is first: `ARGUMENT_RE.finditer` currently extracts matching spans without proving it covered the whole tool body. The published [Tinker SamplingParams reference](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/types/samplingparams/) lists max tokens, seed, stop, temperature, top-k and top-p, but no JSON-Schema/grammar option for this pinned sample route. That absence is a limitation of the checked route, not a claim that no possible model service has constrained decoding. Parser strictness is a safety repair, **not** a guarantee that GLM will submit a valid plan on its next sample.

After this safety repair, separately decide whether the Controller should submit fewer short scientific choices while the trusted broker derives execution bounds. Controller authorship must stay clear; the broker may not select the research question/source or promote a rejected historical answer. Release, zero-provider canary, budget/ID checks and independent review remain required before new paid work.
