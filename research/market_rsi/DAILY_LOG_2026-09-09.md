## 可行方向

### 1. Controller harness

外层使用 Codex，内部 controller 使用 GLM。Harness 要提供长上下文、公开文献搜索、代码执行、
数据体检、非穷尽算法目录、隔离执行和完整日志。Archive 保存过去做过什么、哪里失败、花了多少，
但不预先规定 controller 下一轮必须选择什么。

验收：controller 的每次搜索、读文件、写 candidate、运行和选择都能追到日志；不能读取
Future Test、其他实验路线或密钥。

### 2. 预测目标

旧的短期 mid-price MSE 太小，而且大多数样本不变化。正式目标要在看 Dev 前确定。候选包括：

- 用 bps 表示未来变化；
- future midpoint window mean、EWMA 或 median；
- 有可靠成交数据后加入 future trade VWAP；
- 比较多个预测 horizon；
- 用波动率归一化收益作为辅助目标。

目标可以有多个诊断指标，但每个实验必须预先写明唯一主要目标、基线和失败条件。Dev 不好不能
成为临时换目标的理由；换目标必须开新实验。

### 3. Train / Dev / Future Test

只使用当时真实可见的历史数据。按时间和完整比赛切分，不随机拆行，同一场比赛不能跨集合。
不同集合之间需要 purge / embargo，避免标签窗口跨过边界。每轮 Dev 只打开一次，之后进入下一轮
Train；下一轮换一个更晚、从未打开过的 Dev。Future Test 始终封存到最后。

### 4. 评分

不能只报告一个很小的原始 MSE。每轮至少同时报告：

- RMSE / MAE，以 bps 表示；
- `skill = 1 - candidate_MSE / persistence_MSE`；
- 方向准确率；
- 每天和每场比赛的稳定性；
- coverage、失败数和预测变化幅度；
- 有可靠概率预测时报告校准和 proper scoring rule。

预测稳定后，再单独做包含手续费、点差、滑点和成交概率的交易实验。预测分数不能直接写成盈利。

### 5. 自我改进循环

每轮 researcher 可以查文献、检查 Train、提出目标以外的研究改动、写代码并运行 Train-CV。
Controller 根据可见证据选出一个 candidate。Runner 随后只打开 Dev 一次，把结果写进下一轮
Archive。下一轮根据完整历史继续研究。每轮必须记录查了什么、改了什么、为什么选择、结果和成本。

### 6. Harness 自我改进

正式 Round 中不允许静默修改 harness。每轮结束后可以提出 harness patch；patch 先通过固定
canary、隔离检查和回归测试，再产生明确的新版本，例如 `H0 -> H1`。模型版本、Codex/Claude
Code 版本、工具、配置、instructions 和源码 hash 都要记录。产品自己的隐藏 harness 更新不能
冒充我们的研究进步。

### 7. 市场 replay simulator

优先按真实时间顺序重放历史盘口和成交，让策略在当时的信息条件下预测或交易。完全生成式的金融
simulator 风险更高；只有当生成数据在价格变化、点差、成交量、跳变、相关性和尾部上都能匹配真实
市场时，才能用于训练，而且仍不能替代真实 Future Test。

**2026-09-09 决定：暂缓。** Simulator 本身是一个很大的研究问题，目前无法同时证明它足够接近
真实市场。它保留在研究 Archive 里，但不进入当前 MVP、今天的执行顺序或正式实验依赖。当前实验
只使用真实历史数据和实时采集后封存的数据。

### 8. 交易决策实验

预测研究稳定后，再研究挂单、撤单、仓位和做市。最终指标是扣除手续费、滑点和未成交风险后的结果，
但这与当前预测实验分开，不能混用目标或结论。
